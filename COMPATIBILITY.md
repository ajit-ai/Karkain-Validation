## Language features exercised

- `func`, untyped parameters, `let`, `return`, `while`, `if`/`else`
- arrays: `[]`, `len`, `push`, indexing, mixed element types
- strings: `+`, `len`, indexing, `contains`, `str`, `println`
- comparisons `==`, `!=`, `<`, `>`, `<=`, `>=`; `assert`, `assert_eq`
- `public func` exports, sibling-module `import` and qualified calls
- `karkain check`, `karkain run`, `karkain test`

## Verified semantics used deliberately

- Arrays are values: every rule returns the updated report, which callers
  must capture.
- Comparison expressions yield integer `1/0`; truth checks use `if ok` and
  `if ok == false`. Tests never use `assert_eq(x, true)` on a comparison.
- `len(number)` returns `0` in v1.2.0, so `required` is documented for
  strings/arrays and `require_nonzero` is provided for numeric values.
- Logical `and`/`&&` are unavailable in the verified stable subset; range
  rules use explicit branches.
- Character classification uses the verified `contains` builtin over ASCII
  alphabets rather than regex or Unicode APIs.

## Verified boundaries / limitations

- No top-level `struct`: reports are flat arrays of `[field, rule, message]`
  triples with documented accessors.
- `karkain test` cannot resolve `import`; native tests are generated by
  concatenating the real module source with the test bodies in a temporary
  file.
- Local imports resolve from the entry file's directory; the verification
  script stages the module beside examples.
- `is_email_basic` is a structural check, not RFC 5322 validation.
- Custom rules accept an application-computed predicate result; no function
  pointers or dynamic dispatch are assumed.
- The test driver emits non-fatal Winsock linker diagnostics on this host;
  failure detection was independently verified (exit code 4 on `assert(false)`).

No claim is made about Linux, macOS, mobile, WASM, GPU, NPU, quantum,
networking or database support for this framework.

## Scope boundary

This framework implements reusable data validation only. It does not depend
on Karkain-Testing or any other framework, does not replace compiler
validation, and does not modify the Karkain toolchain or standard library.
